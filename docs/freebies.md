# Union events and society freebies

The moderator’s **Import next 14 days** button reads the live public Students’ Union UCL calendar and opens every event listing. Claude extracts event details, checks for freebies and moderates publication in one request for up to 30 events. Batches shrink when their combined source text exceeds 65,000 characters; an unusually long page is processed alone without truncating its evidence. Ended events are skipped before fetching their pages or spending AI tokens. A valid event with no identified freebie publishes as **event**; an explicit offer publishes as **freebie**. Both remain distinct layers and use the same importer, source identity, moderation and freshness rules. Free admission alone, things for sale, discounts, borrowed equipment and raffle prizes do not qualify as freebies. Explicit items included with a paid ticket can qualify, with the price shown.

Clear, source-backed events pass the combined Claude moderation check and publish automatically. Unclear offered-item prices or flagged content stay in the existing moderation queue for **Approve** or **Reject**. Provider failures remain failed, never implicit approval or a negative finding. Missing extraction or withdrawn source evidence does not create an event. Reports and moderator hiding continue to use the existing community system.

## Source and API contract

The importer uses the anonymous JSON source behind the [Union calendar](https://studentsunionucl.org/whats-on): `/json/anon/whats-on/{startUnixSeconds}/{endUnixSeconds}/list/{zeroBasedPage}`. It follows pagination until an actually empty page, filters the date interval locally and deduplicates ticket variants. A short page is not the last page. The Union [documents that ticket times can create separate calendar occurrences](https://studentsunionucl.org/how-to/website/manage-events-with-many-time-slots-entry-times).

The feed supplies title, occurrence dates, venue labels, organising groups and an online flag, but no coordinates and no complete description. The importer reads each event's public article and separate booking block for the remaining facts. It retains source organiser and explicit online metadata; unknown or ambiguous venues stay unlocated. The reviewed [robots file](https://studentsunionucl.org/robots.txt) does not disallow the calendar JSON or event paths, but does disallow `/sites/default/files/`; this importer does not fetch those image files. Requests stay on the Union host and do not sign in or crawl external ticket sites.

The existing `/api/freebies/*` paths and `freebie` metadata property are retained for compatibility. `GET /api/freebies/feed` returns approved `event` and `freebie` records ending after now and starting before London midnight fourteen dates after today. `?type=event` and `?type=freebie` select one category. Pagination remains 50 records per response with `nextOffset`. Source links, last-check times, unknown locations and the latest scan status remain visible; an incomplete scan is not complete event coverage.

The research check on 15 October 2026 verified one live feed page and one public event page. It did not run or publish a full two-week import. A source-backed snapshot requires a completed, authorised import; there is no bundled claim that these listings have already been loaded.

## Background operation

The import starts a Next.js after() worker; the HTTP response returns immediately. Each stage (page fetch, Claude extraction, publication) is persisted before advancing. A bounded worker fetches and publishes three events at a time, fills text-bounded AI batches of up to 30, then sends an authenticated continuation to **/api/freebies/worker**. Closing the browser does not pause it.

Database leases prevent overlapping workers, expire after a crash, and are released with a token check. Transient provider requests have bounded retries. A failed import automatically retries its saved failed stages twice without redoing successful stages. Invalid credentials and repeated failures stop visibly; fix the configuration and use **Import next 14 days** to resume an active scan. New calendar reads are limited to one start per hour; active imports resume without another discovery.

This is a resumable worker, not a hosted durable queue. A hard process termination or failure to deliver all three continuation attempts can stop the chain. Saved work remains intact. The Import button recovers it; for unattended recovery register an authenticated **POST** to **/api/freebies/worker** every five minutes. Recovery never starts a new date window. Logs intentionally omit source bodies, keys and auth headers.

The route requests 300 seconds of function duration, using a 65-second launch budget so the last bounded provider stage can finish. Batched Claude requests have a 90-second deadline and make one transport attempt per saved stage; failed events retry in groups of at most five. Enable Vercel Fluid Compute, or use an equivalent runtime supporting that duration. See [Vercel function duration](https://vercel.com/docs/functions/configuring-functions/duration).

## Daily import — registered, off until enabled

`vercel.json` registers one daily **GET /api/freebies/daily** invocation at **05:00 UTC**. Vercel installs that schedule when this configuration reaches the production deployment; this PR does not change hosted settings or start an import. The route still requires the secret, source flag, daily flag, database, Claude and continuation URL. With either import flag off, it cannot start a scheduled import.

Vercel sends the production `CRON_SECRET` as **Authorization: Bearer …** automatically. The app compares it before doing any work; opening the endpoint in a normal browser returns 401. Schedules use UTC, so the nominal local time is 06:00 during British Summer Time and 05:00 in winter. Vercel invokes only the production deployment, not branch previews. See [cron operation](https://vercel.com/docs/cron-jobs) and [cron authentication](https://vercel.com/docs/cron-jobs/manage-cron-jobs#securing-cron-jobs).

Hobby supports this once-daily schedule, with delivery anywhere within **05:00–05:59 UTC**, rather than an exact-minute guarantee. A more frequent cron expression would fail a Hobby deployment. Do not add a five-minute worker schedule to `vercel.json` on Hobby. [Vercel cron limits](https://vercel.com/docs/cron-jobs/usage-and-pricing).

After enabling and deploying, check the next run in **Settings → Cron Jobs → View Logs** and the app's import history. An accepted trigger returns 202; it is not proof that every event has finished processing. Vercel does not retry a failed cron invocation, so inspect failures and use the Import button to recover saved work. Duplicate calls on the same London date do not start another window. Turning `FREEBIE_DAILY_IMPORT_ENABLED` off stops scheduled new imports; turning `UNION_IMPORT_ENABLED` off stops subsequent worker invocations as well. Redeploy after changing these flags. [Cron error handling](https://vercel.com/docs/cron-jobs/manage-cron-jobs#cron-job-error-handling).

## Locations, freshness and cost

- Campus names and aliases are tried first. Room labels map to an existing building point, not an invented entrance. North Cloisters / Housman Room aliases use [UCL’s location page](https://www.ucl.ac.uk/staff-common-room/how-find-us).
- Only a unique name-matched London Google result is accepted. Ambiguous, online, TBC and unmatched venues remain in the list without a map pin. Moderators can confirm an existing campus building; that correction survives later imports until the source changes venue.
- Google coordinates are cached for at most 30 days; IDs can be retained. Unknown results are cached for one day. Simultaneous identical lookups share a request. Names, addresses, photos and reviews from Google are not persisted. Results requiring additional third-party attribution stay unlocated.
- Google positions render only while the map uses Google tiles. The OpenStreetMap fallback hides those pins. Public serializers suppress expired Google positions; worker housekeeping removes stored coordinates. If Google fallback is enabled, register the recovery worker at least daily so removal runs even between imports. [Places policies](https://developers.google.com/maps/documentation/places/web-service/policies), [cache terms](https://cloud.google.com/maps-platform/terms/maps-service-terms).
- Identity is the Union product plus occurrence start time, so ticket variants and end-time edits update one pin. Different recurrence dates retain distinct pins. A changed start time is a new occurrence; the older pin expires at its original end. A validated change between event and freebie updates that same record. An explicit source withdrawal hides its prior pin. Moderator decisions are preserved during rescans and concurrent AI calls. A removed listing is not inferred from an incomplete feed; existing records still expire at their saved end time.
- The scan covers London today through the next 13 days, including events already running. Pin expiry is the event end, capped at the end of that fourteen-date London window; source event end remains separate metadata for display. Missing or invalid end times remain a visible processing failure rather than receiving an invented duration. Student posts retain seven days and leftover food alerts six hours. The separate single-listing moderator form also accepts fourteen days.
- **2 weeks** is the default time filter. Now includes running events; This week ends at Monday midnight London time; 2 weeks includes fourteen calendar days. London’s daylight-saving transition is tested. Ordinary events use blue and freebies use purple, with upcoming start times labelled. Freebie item evidence appears only for source-backed offers. Ended pins disappear without a refresh.
- Society and dietary details require source quotes. Missing details are labelled. A dietary tag is not an allergen or food-safety guarantee.
- Raw source page checkpoints on completed/rejected events are cleared in bounded housekeeping after 30 days. Unresolved audit evidence stays private behind moderator authentication and RLS. CSV exports neutralise spreadsheet formulas.

The legacy Jev settings and provider code remain compatible with old checkpoints, but **FREEBIE_JEV_SCREENING** no longer skips listings in this importer. A low freebie score cannot exclude an ordinary event or replace complete event extraction. Claude checks every listing, including a resumed task with a saved low Jev score. The maintenance `recheck` action also requeues old `no_freebies` tasks. [Claude Messages API](https://platform.claude.com/docs/en/api/messages/create).

## Batched extraction and publication (October 2026)

- The current importer combines extraction and moderation per event within a single structured response, up to 30 events per request. This is synchronous multi-event prompting, not Anthropic’s asynchronous Message Batches API, and does not claim its pricing discount. Calls and repeated prompt overhead decrease; billing still depends on input/output tokens. Haiku 5.5 defaults to adaptive thinking; the importer requests low effort for this routine work and omits unsupported sampling settings. Other model overrides do not receive Haiku-specific effort settings. Provider access and extraction quality still need confirmation against the operator's account and real listings after deployment.
- Every result must echo its own task ID and pass schema, source-quote and moderation validation. Missing, duplicated or invalid rows fail individually. Successful extraction and approval checkpoints survive retries; the importer does not repeat successful events to repair a failed sibling. HTTP/truncation failures retry the affected pending events in smaller groups.
- A fresh scan fetches public pages again to detect changes. It reuses a prior combined result only when the complete source/page fingerprint, model and versioned extraction/moderation policy match. Changed source text, title, venue, dates, links, model or policy trigger a new check. Local privacy checks and moderator decisions always remain in force. Legacy checkpoints without a combined verdict retain the separate moderation check when resumed. No database migration or extra environment variable is needed.
- The import panel now separates events found, pages read, saved AI checks, published records and confirmed map locations. The public sidebar shows how many published events have coordinates and has a **Show published events** button, which clears search/category/date filters and opens the event list. Online and unconfirmed venues are included in that list but never given invented map coordinates.
- Deploy this PR to Production before resuming an unfinished import with **Import next 14 days**. An already-running old worker may finish its current invocation using the old code; saved successful stages are retained. Verify **FREEBIE_WORKER_URL** uses the public production domain and is reachable without Vercel deployment protection: a protected callback can leave a scan marked running with unchanged progress. The Import button resumes saved work after fixing that configuration.
